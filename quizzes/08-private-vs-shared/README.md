# Quiz 08 — 이웃의 폭식에서 내 hot 페이지 지키기 (scan resistance)

## 시나리오

1. **세션 A**: t_hot(~30페이지)을 여러 번 스캔해서 뜨겁게 만든다.
   재스캔 시 `ioreads ≈ 0`임을 확인한다 (완전히 캐시됨).
2. **세션 B**: t_big(~920페이지, 풀보다 작지만 quota보다 훨씬 큼)을 **2회** full
   scan 한다 — Quiz 05에서 봤듯 자기 quota 안에서 thrashing이 일어난다.
3. **세션 A**: t_hot을 다시 스캔한다. **디스크에서 다시 읽어야 할까?**

전역 LRU 하나였다면 B의 ~1,800회 페이지 읽기가 A의 30페이지를 확실히 밀어냈을
상황이다.

## 실행

```bash
./run.sh
```

## 문제 (4지선다)

3단계에서 세션 A의 t_hot 재스캔 결과는?

- **(a)** 전부 디스크에서 다시 읽는다 — 대량 스캔이 캐시를 쓸어 갔다.
- **(b)** **거의 전부 hit** — B의 스캔은 B 자신의 private LRU quota 안에 격리되어
  있었으므로, A의 페이지는 건드려지지 않았다.
- **(c)** 절반쯤 hit — LRU 중간까지만 밀려났다.
- **(d)** 카탈로그 페이지만 hit하고 데이터 페이지는 다시 읽는다.

> 힌트: Quiz 05에서 B의 victim은 전부 어디서 나왔었나?
> (`Num_victim_own_private_lru_success`)
