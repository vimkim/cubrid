# Quiz 02 — fix/unfix: 쿼리가 끝나면 페이지는 몇 장 "고정"되어 있을까

## 시나리오

수백 페이지를 읽는 쿼리를 실행한 **직후**, 버퍼 풀 게이지를 관측한다.

- `Num_data_page_fetches` — `pgbuf_fix()` 호출 횟수 (누적)
- `Num_data_page_fixed` — 지금 이 순간 fix count > 0 인 페이지 수 (게이지)
- `Num_data_page_lru1/lru2/lru3` — LRU 각 zone에 있는 페이지 수 (게이지)

배경: 실행기는 페이지를 쓰는 동안만 `pgbuf_fix()`로 페이지를 "빌리고", 다 쓰면
`pgbuf_unfix()`로 돌려준다. fix는 대출, 버퍼 상주는 진열이다.

## 실행

```bash
./run.sh
```

## 문제 (4지선다)

수백 페이지를 읽은 쿼리가 **완료된 직후**, `Num_data_page_fixed` 게이지는 대략?

- **(a)** 쿼리가 읽은 페이지 수와 같다 — 읽힌 페이지는 세션이 끝날 때까지 고정된다.
- **(b)** **거의 0** — fix는 페이지를 만지는 몇 마이크로초 동안만 잡는 대출이고,
  쿼리가 끝나면 전부 반납된다. 페이지 자체는 LRU에 남아 캐시된다.
- **(c)** LRU zone 1에 있는 페이지 수와 같다.
- **(d)** dirty 페이지 수와 같다 — dirty인 동안은 unfix할 수 없다.

> 힌트: "버퍼에 남아 있다"와 "fix되어 있다"는 다른 상태다. 전자는 캐시,
> 후자는 지금 누가 쓰는 중이라는 뜻이다.
