# Quiz 01 — Cold read vs Hot read: 버퍼 풀은 무엇을 캐시하나

## 시나리오

서버를 재시작해서 버퍼 풀을 완전히 비운 뒤(**cold cache**), 같은 테이블을 `SELECT COUNT(*)`로
**두 번** 스캔한다. 각 스캔 전후의 perfmon 카운터 델타를 관측한다.

- `Num_data_page_fetches` — page buffer에 페이지를 요청(`pgbuf_fix`)한 횟수
- `Num_data_page_ioreads` — 실제로 디스크에서 페이지를 읽어온 횟수

## 실행

```bash
./run.sh        # 서버 재시작 포함, debug 빌드에서 몇 분 걸릴 수 있음
```

## 문제 (4지선다)

같은 `SELECT COUNT(*)`를 재시작 직후 한 번, 곧바로 또 한 번 실행했다. 관측 결과로 옳은 것은?

- **(a)** 두 스캔 모두 디스크 읽기가 비슷하게 발생한다 — 버퍼 풀은 쿼리 결과만 캐시하기 때문.
- **(b)** 1차 스캔은 `ioreads > 0`, 2차 스캔은 `ioreads ≈ 0`이지만 `fetches`는 두 번 모두 비슷하게 발생한다.
- **(c)** 2차 스캔은 `fetches = 0`이다 — 첫 실행의 결과가 SQL 캐시에 저장되었기 때문.
- **(d)** 1차 스캔의 디스크 읽기 횟수는 테이블의 행(row) 수와 같다.

> 힌트: 버퍼 풀이 캐시하는 단위는 무엇인가? 그리고 "페이지를 요청하는 것"과
> "디스크에서 읽는 것"은 언제 달라지는가?
